# 文章结构与渲染约定

写作完成后由 `scripts/build_html.py` 渲染成 HTML 图文单页。先按本文件组织每篇文章的文件夹与内容。

## 目录约定

```
output/第N周/
├── index.html                # 周目录页（build_html 自动生成）
└── <slug>/
    ├── article.md            # frontmatter + Markdown 正文（手写）
    ├── index.html            # 本篇文章页（build_html 自动生成）
    └── img/                  # 本篇文章配图
```

## article.md frontmatter

```markdown
---
title: "一篇能解决××问题的标题（含关键词）"
keyword: "本周关键词"
tags:                     # 智能标签：Agent 按文章内容/关键词/组别生成 3-5 个，upload 时自动写入 CMS Tags 字段
  - "标签1"
  - "标签2"
  - "标签3"
group: "教程操作"            # 10 组之一：下载安装/价格购买/对比选择/模板获取/格式转换/故障解决/教程操作/功能认知/AI认知/品牌直达
content_strategy: "中关联(通用+WPS章节)"   # 内容策略：高关联(整篇WPS)/中关联(通用+WPS章节)/低关联(方法论轻带)，决定正文模板
meta_title: "SEO 标题（可不填，默认取 title）"
meta_desc: "SEO 描述，80 字内（可不填，自动截取正文）"
date: "2026-08-27"        # 仅内部记录，正文页不渲染日期
image: "img/cover.jpg"        # 封面主图（可不填）
faq:
  - q: "问题一"
    a: "直接给结论的回答。"
  - q: "问题二"
    a: "先结论后依据。"
sources:
  - "https://bbs.wps.cn/topic/xxxx"   # 仅内部溯源，正文页文末不渲染参考来源
---

正文 Markdown 从这里开始……
```

> **灵犀化题材**：标题可与 WPS 相关，正文聚焦“用 WPS 灵犀完成 xxx”。frontmatter `keyword` 仍记录关键词；`group` 落组后按组别改写为灵犀能力演示/教程。

## 正文结构骨架（按内容策略三套模板微调）

> **灵犀能力硬性植入**：三套模板均要求正文植入 WPS 灵犀能力（高关联=全文围绕灵犀；中/低关联=至少一个独立章节或明确段落），能力表述以资源池多维表中灵犀/AI 素材的官方描述为准，不得杜撰。

> 正文页（CMS Content）渲染时**不含组别 tab、不含 H1 标题、不含日期、文末不含参考来源、不含下载 CTA**（结构最终参照草稿 2666），直接图文；标题由 CMS Title 字段管理。

写作前先看关键词自带的 `内容策略` 标签（keywords 技能输出），选对应模板；未标注时按本文件「内容策略判定」判断。

### 内容策略判定（无标签时用）

| 关键词特征 | 内容策略 | 说明 |
|-----------|---------|------|
| 含 灵犀/wps/金山/官网/会员/office/AI 等品牌词，或价格/下载词 | **高关联(整篇WPS)** | 整篇围绕 WPS 灵犀，灵犀是主角 |
| 教程/故障/模板/认知/场景词（非品牌导向） | **中关联(通用+WPS章节)** | 先讲通用方法，某章节带出**用灵犀加速** |
| 纯通用方法论词（如何做周报/工作总结等） | **低关联(方法论轻带)** | 讲通用方法论，独立章节介绍灵犀提效（灵犀植入红线仍适用） |

### 模板 A：高关联（整篇WPS）——品牌词/价格/下载词

```markdown
# 开头：3 句内抓人（给结论/数字/痛点），直接点明“用 WPS 灵犀就能解决”

## WPS 灵犀是什么 / 为什么用它
（一句话讲清灵犀是 WPS 官方 AI 助手、适用人群）

## 具体怎么做（分步 + 配图）
（全程“打开灵犀→输入指令→得到结果”路径，每步配 img/ 截图）

## 进阶能力 / 小技巧
（补充灵犀的其他能力，如 AI 写作/表格/PPT/PDF/阅读，加强价值）

## 常见疑问（正文内先答 1–2 条，展开的放 FAQ）

## 小结
（收束 + 引导体验 WPS 灵犀）
```

### 模板 B：中关联（通用+WPS章节）——教程/故障/模板/场景词

```markdown
# 开头：讲清用户要解决什么问题（通用层面），痛点场景开场

## 这个问题是什么 / 通用解决方法
（先给通用概念与通用做法，配通用操作图）

## 用 WPS 灵犀也能快速解决
（带出灵犀里的对应操作路径，配灵犀截图，软性植入）

## 常见疑问

## 小结
（收束 + 软引导：如果你在用 WPS，可以体验一下）
```

### 模板 C：低关联（方法论轻带）——纯方法论词

```markdown
# 开头：讲通用方法论、适用场景

## 方法论核心步骤
（通用框架）

## 提高效率的小工具参考
（独立章节：按资源池官方表述介绍灵犀对应能力，软性植入但不缺位）

## 常见疑问

## 小结
（收束方法论）
```

### 组别 → 各模板内的侧重（仍参考）

- **教程操作/格式转换/故障解决**：模板 B 通用主体 + **灵犀/WPS 章节**；若为灵犀/AI 品牌词走模板 A
- **对比选择/价格购买**：模板 A（品牌词）或模板 C（方法论），客观对比、不贬低对手
- **功能认知/AI认知/品牌直达**：模板 A（整篇讲 WPS 灵犀功能/AI 能力）
- **模板获取**：模板 B（通用模板需求 + 用灵犀生成/查找模板 章节）

## 配图插入

配图**一律使用真实产品截图**，且**只从 SEO 图片资源库获取**（规则详见 style-guide 第 7 节）：每篇 1–2 张、开头不放图、匹配度 > 80%、当天文章间重复度 ≤ 20%、无合适图可不配，禁用 AI 示意图。

正文中直接使用相对路径引用：

```markdown
![用WPS灵犀一句话生成PPT](img/lingxi-ppt.png)
```

- 封面图在 frontmatter `image` 字段声明，渲染为文章头图。
- 关键段落图放正文，渲染在对应标题下方。

## 渲染调用

```bash
python scripts/build_html.py --articles-dir output/第3周
```

- 每篇输出 `<slug>/index.html`（自包含单页，内联 CSS），周目录输出 `index.html`。
- 浏览器直接打开 `index.html` 即可预览完整图文效果。

## 上传 CMS 草稿箱（不发布）

- 把每篇 `<slug>/` 整目录（`index.html` + `img/`）上传到 CMS 后台的草稿箱/草稿状态，**只存草稿、不发布**。
- 平台与操作方式见 `references/cms-upload.md`。
